# 트바 작업 오케스트레이션

이 절차는 사용자의 요청을 받은 마스터가 실행한다. Orca에서 Task·Dispatch ID가 포함된 요청을 받았다면 작업자다. 작업 범위와 완료 조건을 따르고, 주입된 명령으로 완료 보고를 보낸다.

## 시작과 판단

1. 버전에 맞는 `orca skills get orchestration`을 읽는다. 여러 단계가 의존하면 `--reference references/coordinator-loop.md`도 읽는다. Orca Mac 로컬에서 실행하며 다른 호스트에 작업을 보내지 않는다.
2. 사용자 요청, PRD, 요구사항, ADR, 현재 브랜치와 변경 내역을 확인한다. 기획 중이거나 미승인 범위인 아이디어는 요구사항·설계 초안과 검증으로 진행한다. 구현 요청에는 기능과 완료 기준을 정한 뒤 구현을 맡긴다. 아이디어가 기존 방향과 맞으면 가역적인 선택은 근거를 남기고 진행한다.
3. 제품 방향·출시 범위 변경, 실제 사용자 데이터나 개인정보 처리 방식 변경, 비용이 발생하는 서비스, 배포·외부 공개, 인증·서명, 되돌리기 어려운 데이터 변경처럼 명시적 결정을 받아야 할 때만 사용자에게 묻는다. `gate-create`로 해당 후속 Task를 막고, 확정할 질문·선택지·추천 이유를 함께 제시한다. 사용자 답을 받을 때만 `gate-resolve`로 해제한다. 기기 연결이나 시스템 권한이 실제로 필요할 때는 그 시점에 알린다. 게이트와 관계없는 작업은 계속 진행한다.

## 개발과 리뷰

1. 새 요청마다 `orca orchestration run-create --objective "<목표>"`로 Run을 만든다. `task-create`에 담당 범위, 허용한 변경, 검증 방법, 산출물과 완료 기준을 적는다. 사용자 미커밋 변경은 공유 브랜치에 반영하지 않는다. 작업자에게 필요한 요구사항과 맥락은 Task에 포함한다.
2. 개발에는 `worker-start --task <id> --worktree new-child --name <작업명> --setup skip --agent claude`를 사용한다. 서로 의존하지 않고 동시에 편집해도 충돌하지 않는 작업만 별도 worktree에서 병렬로 시작한다. 마스터가 이전 작업 결과를 받아야 하는 일은 deps로 연결하거나 결과가 도착한 후 Task를 생성한다. 작업자에게 종료 시 테스트 결과와 정확한 커밋 또는 diff 경로를 `worker_done`으로 보고하게 한다. 작업자 모델은 Orca와 프로젝트 기본값을 사용하며 사용자가 해당 역할의 모델을 지정하면 그 모델을 전달한다.
3. 구현 보고를 받으면 `task-list --ready --brief`로 진행 가능한 작업을 갱신한다. 변경이 남는 작업은 동일한 diff를 대상으로, 개발자와 별개의 검토 세션에 REVIEW.md, 기준 커밋, 인수 기준과 테스트 증거를 넘긴다. 단순 문서·작은 변경은 Claude 읽기 전용 검토 작업자를 사용할 수 있다. 앱 동작, 로그인, 데이터 권한, 위치, 순위 계산이 바뀌거나 변경이 크면 `--agent codex`로 독립 리뷰를 맡긴다. 개발 worktree를 그대로 읽게 하고 파일 수정은 맡기지 않는다. 같은 worktree를 동시에 편집하는 작업자는 두지 않는다.
4. 여러 브랜치를 통합하는 경우 먼저 별도 통합 worktree에서 정확한 커밋들을 합치고, 합친 결과에 대해 검사와 최종 리뷰를 한다. 중요 지적은 구현 작업자에게 전달하고 변경된 검사와 리뷰를 다시 실행한다. 현재 권한 및 환경에서 확인하지 못한 것은 결과에 명시한다. 완료된 후보는 검토된 로컬 커밋으로 남기고, main 병합·푸시·배포는 사용자가 해당 작업에서 승인했을 때 진행한다.

## 완료 보고와 재개

- 작업자를 시작한 뒤 턴을 끝낸다. Orca가 보낸 완료·질문 메시지로 재개한다. 채팅에 본문이 오면 처리하고, `check` 명령을 안내받았을 때만 실행한다. 백그라운드 메일을 가져오는 폴링 스크립트는 사용하지 않는다.
- 판단할 수 있는 작업자 질문은 바로 답한다. 실패한 Task는 성공으로 기록하지 않는다. 실패 원인을 확인해 가능한 범위에서 고치고, 응답이 불분명한 실행은 버전에 맞는 복구 가이드에 따라 기존 상태를 확인한다.
- 최종 응답에는 수행 작업, 결과 커밋 또는 파일, 검사·리뷰 결과, 확인하지 못한 항목을 짧게 적는다. 실기기 검증이 남았다면 연결이 필요한 시점을 알려준다.

## 읽기 전용 연결 시험

사용자가 오케스트레이션 자체의 연결 시험을 요청하면 위의 제품 작업 대신 같은 worktree에서 읽기 전용 Claude 작업자를 시작한다. `worker_done` 이후 별도 Codex 작업자가 결과를 확인하고 `worker_done`을 반환하는지 검증한다. 시험은 파일 수정 없이 진행하고 두 보고의 수신 여부를 요약한다.
