# ADR-005 방문 인증 처리와 위치 정보 최소화

- 상태: **제안**
- 날짜: 2026-11-24
- 관련 요구사항: F-040~F-044, NF-003

## 맥락

평가 시 사용자 위치가 식당에서 200m 이내이면 평가에 '방문 인증' 배지를 붙인다. 위치는 민감한 개인정보이므로 최소한으로 다루고, 인증 실패가 평가 저장을 막지 않아야 한다.

## 고려한 선택

| 선택 | 평가 |
| --- | --- |
| 기기에서 거리 계산 후 결과만 전송 | 좌표가 서버로 가지 않아 개인정보에 유리. 결과를 클라이언트가 임의로 조작 가능 |
| **서버에서 판정, 좌표는 일회성 전달·비저장 (추천)** | 식당 좌표가 서버에만 있어 단순 위조 어려움. 좌표가 전송 구간을 지나지만 저장·로그 없음 |
| 좌표를 저장해 사후 검증 | 추적 가능성·유출 위험이 커 불필요 |

## 결정과 이유

서버(`submit_review` 함수)에서 판정하고 원본 좌표·정확도·측정 시각은 **저장·로그하지 않는다**(세부 표는 [아키텍처](../architecture/ARCHITECTURE.md#위치-인증-처리)). 저장하는 것은 판정 결과, 사유, 판정 시각, 기준 버전, 식당 좌표의 출처뿐이다. 사용자에게는 "식당 근처에서 평가했다"는 의미로만 설명하고 보안 인증이라고 하지 않는다.

기준값(200m, 정확도 100m, 측정 60초)은 `verification_rule_version`으로 버전을 기록한다. 정확도·측정 시각 기준은 **제안값**이며 첫 실기기 측정(실내·골목·고층)을 보고 조정한다.

## 영향과 재검토 조건

- 서버 로그·모니터링·오류 보고 도구에 요청 본문이 남지 않도록 설정하는 것이 필요하다(코드 리뷰 항목).
- 재검토: 인증 성공률이 낮을 때(정확도 기준 완화 또는 거리 보정), 위조가 실제 문제가 될 때, 점수 가중치를 도입할 때.
